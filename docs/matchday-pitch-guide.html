1. What MatchDay solves

Most tournament work is scattered across spreadsheets, chat messages, paper check-in lists, court announcements, and separate scoring tools. MatchDay brings the complete tournament lifecycle into one system: discover an event, register, create the draw, schedule courts, score matches live, publish results, and keep everyone aligned.

For organizers

Create and operate a tournament with fewer manual handoffs, clearer status, and a single source of truth.

For players

Register, check in, see your next match, follow live scores, and keep a history of results.

For scorers and officials

Use a focused courtside scoring experience with match state, games, corrections, and offline resilience.

For viewers

Follow public draws, schedules, courts, results, and live matches without needing an account.

2. End-to-end workflow

  1. Create: organizer defines name, venue, dates, sport, courts, categories, capacity, fees, and registration fields.
  2. Register: players enter singles or doubles categories; waitlists and registration states are supported.
  3. Prepare: organizer reviews participants, check-in, seeds, staff, officials, and category readiness.
  4. Draw: generate knockout, round-robin, or groups-to-knockout formats; pairings and rounds become visible.
  5. Schedule: assign matches to courts and times with conflict detection and rescheduling support.
  6. Play: scorer records games and points live; court status and match state update across the app.
  7. Finish: completed results flow to the draw, player history, rankings, analytics, and public tournament page.

5. Technology and architecture

Frontend

React 19, Vite, React Router 7, Tailwind CSS 4, Lucide icons, and Motion for focused transitions.

Backend

Supabase with PostgreSQL, authentication, Row Level Security (RLS), Realtime, Storage, and Edge Function boundaries.

Application design

Repository pattern: Supabase calls live in src/lib/repository.js. UI components do not query the database directly.

Rules engines

Pure, testable modules handle draws, scoring, scheduling, rankings, series standings, lifecycle, validation, and intelligence.

Security & privacy

Roles are scoped per tournament. RLS is the security boundary. Sensitive participant details are separated from public name-only views.

Delivery

Production deployment is Git-based through Vercel. Lint, unit tests, scheduling tests, migration checks, and production builds are available in CI.

6. Honest product status

What works end to end: authentication, tournament creation, registration and waitlists, configurable fields, draws, seeding, scheduling, check-in, badminton live scoring, offline scoring queue, disputes, staff/RBAC, in-app notifications, rankings, series, finance, analytics, exports, branding, public pages, discovery, venue display, and tournament intelligence.
Important caveats: payments currently use a mock provider for click-through demonstrations; Razorpay is not connected. Notifications are in-app until provider secrets and dispatch functions are deployed. Email, SMS, WhatsApp, and push are not connected. Pending migrations should be applied and verified before treating the production project as fully hardened.
